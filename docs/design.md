# 设计说明

工作台将浏览器中的工作会话映射为持久会话记录、独立工作目录和 Codex thread。HTTP 服务负责用户操作与生命周期，CLI 负责模型决策、工具调用和文件修改。

## 执行与恢复

发送消息先落盘，再进入有界队列。每个会话只运行一个任务，跨会话默认允许两个并发。CLI 的 JSONL 事件写入追加日志，并通过 SSE 提供给浏览器；页面关闭不会取消进程。续聊使用记录中的 thread ID 调用 `codex exec resume`。

运行状态为 `queued → running → completed`，异常时进入 `failed`、`timed_out`、`cancelled` 或 `interrupted`。停止服务时不再取新任务；再次启动将未结束的任务标记为中断。保留文件供用户检查，避免自动重放有副作用的命令。进程退出和输出管道关闭分别处理，避免后代进程持有管道时界面永久忙碌。

## 会话管理

`pinned` 和 `archived` 是会话元数据，旧数据默认均为 `false`。置顶优先，再按更新时间排序；搜索在当前范围中按名称匹配。归档保留成果和消息，并由服务端拒绝继续执行或上传，恢复后可继续工作。

元数据更新整体校验后才修改，类型错误、未知字段和忙碌时归档均不会造成部分写入。浏览器异步操作在开始前固定会话 ID；切换页面不会把尚未完成的发送或批量上传转移给其他会话。

## 文件与交付

浏览器文件接口检查相对路径和每级符号链接。文本预览作为文本渲染，HTML 不在应用源域执行。成果 ZIP 只读取 `outputs/` 下可见普通文件，使用 UTF-8 文件名、CRC32 和标准 ZIP32 目录结构；采用不压缩的存储方式，避免运行依赖和额外压缩开销。32 MB 的容量限制约束内存使用，打开后的文件类型、大小及修改时间用于检查读取期间的变化。

执行历史从持久事件日志读取，每轮显示相应的工具记录。CLI 返回的 token 统计保留原始语义，不据此计算费用。Markdown 导出用于人阅读，JSON 导出保留消息、运行和文件索引等结构。

## 模型与信任边界

Codex 使用 Responses 协议；兼容服务若仅提供 Chat Completions，服务端转换消息、工具调用和工具结果，并封装回 Responses SSE。真实工具执行仍由 Codex 完成。上游凭据不发给浏览器，CLI 只获取本地桥接用的短期 token。

当前面向可信单用户。会话目录是逻辑分离，容器也未按每次任务单独拆分；不是针对恶意脚本的安全沙箱。多用户服务需要独立任务容器、身份认证、配额和更严格的凭据隔离。

## 验证方式

基础 Agent 验证使用真实 CLI、真实模型及 Docker，保留原始产物和命令证据。归档、置顶、下载、异常和协议边界使用确定性测试；浏览器增强功能验证使用已完成任务的离线快照，不重复调用模型，也不把回放当作新的模型运行。
